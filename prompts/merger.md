# 万神殿 · 增量合并器

> 本模板用于 /pantheon-memory 流程：当用户追加新素材时，如何安全地更新现有的 soul.md 和 memory.md。
> 核心原则：只追加，不覆盖；有冲突先问，不擅自决定。

---

## 触发场景

用户追加新素材的方式：
- 粘贴新找到的聊天记录
- 口述新想起的记忆片段
- 其他家人提供的信息
- 找到的旧照片/书信/日记的文字内容
- 明确说"我想补充一些关于[称呼]的信息"

---

## 合并流程

### 第一步：解析新素材

使用与初次分析相同的分析器处理新素材：

1. 用 `memory_analyzer.md` 提取记忆维度（七维分析）
2. 用 `soul_analyzer.md` 提取灵魂特征（六维分析 + 标签检测）

**输出：**
```yaml
new_material:
  source_type: "[聊天记录/口述记忆/书信/第三方转述/...]"
  date_range: "[素材涵盖的时间范围]"
  volume: "[条数/字数]"
  
  memory_extractions:
    key_events: [...]
    daily_rituals: [...]
    oral_stories: [...]
    shared_memories: [...]
    preferences: [...]
    era_marks: [...]
    unfinished_wishes: [...]
    
  soul_extractions:
    linguistic_features: [...]
    emotional_patterns: [...]
    value_indicators: [...]
    new_tags_detected: [...]
    behavioral_rules: [...]
```

---

### 第二步：分类——记忆 vs 灵魂

每条提取结果需要判定去向。部分内容同时影响两个档案。

| 提取内容 | 去memory.md | 去soul.md | 去两者 |
|---------|------------|----------|-------|
| 新的人生事件 | 是 | - | 如果改变了对TA性格的理解 |
| 新的日常习惯 | 是 | - | 如果揭示了新的行为模式 |
| 新的口头故事 | 是 | - | 如果包含新的语言样本 |
| 新的共同记忆 | 是 | - | 如果揭示了新的关系动态 |
| 新的偏好信息 | 是 | - | - |
| 新的语言样本 | - | 是 | - |
| 新的情感模式证据 | - | 是 | - |
| 新的性格标签触发 | - | 是 | - |
| 新的关系动态信息 | - | 是 | memory.md也更新关系概述 |
| 新的时代背景信息 | 是 | 是 | 两边都要更新 |

---

### 第三步：冲突检测

将新提取的内容与现有档案逐条比对，判定关系类型：

#### 类型A：补充（Supplements）

新内容为现有条目增加细节，不改变含义。

```
现有记忆：[称呼]每天早上6点起床
新素材：[称呼]每天早上6点起床，起来第一件事是泡茶，用的是一个搪瓷缸子

判定：补充
操作：在现有条目后追加新细节
```

#### 类型B：确认（Confirms）

新内容与现有条目含义一致，只是来自不同来源。

```
现有记忆：[称呼]是个沉默的人（来源：用户口述）
新素材：聊天记录显示[称呼]80%的消息不超过5个字

判定：确认
操作：不重复添加，但更新置信度——标记为"多源验证"
```

#### 类型C：矛盾（Contradicts）

新内容与现有条目有实质性冲突。

```
现有灵魂特征：[称呼]从不直接表达爱（标签：爱在心口难开）
新素材：用户的姐姐说"爸爸其实经常跟我说想你们"

判定：矛盾
操作：不自动处理，提交用户确认
```

**矛盾处理流程：**

```
守殿人：我在新素材中发现了一些和现有档案不太一样的地方，想跟你确认一下：

现有档案中，[称呼]的特点是"从不直接说想念"。
但新素材中提到，[称呼]会直接跟[姐姐]说"想你们"。

你觉得哪个更准确？还是说两个都对——TA对不同的人表达方式不一样？

[等待用户回答]
```

可能的用户回答和对应处理：
- "两个都对"→ 更新关系行为，记录TA对不同子女的不同表达方式
- "TA不会直接说的"→ 保留现有档案，标记新素材为"存疑"
- "TA其实会说的，我之前说错了"→ 更新现有档案

### 第四步：存档当前版本

在做任何修改前，备份当前版本。

**备份命名规则：**
```

├── [称呼]_[姓名]/
│   ├── soul.md                 ← 当前版本
│   ├── memory.md               ← 当前版本
```

### 第五步：应用补丁

**原则：只追加，不覆盖。**

使用 Edit 工具对 soul.md 和 memory.md 进行增量修改。

#### memory.md 的补丁操作

| 操作类型 | 方式 | 示例 |
|---------|------|------|
| 添加新事件 | 在时间线的正确位置插入新行 | 在1995年和1998年之间插入1997年的事件 |
| 补充现有事件细节 | 在现有条目后追加细节 | 在"每天6点起床"后加"第一件事是泡茶" |
| 添加新故事 | 在口头故事库末尾追加新故事 | 追加"故事4：当年下乡的事" |
| 添加新共同记忆 | 在共同记忆末尾追加 | 追加新的记忆条目 |
| 更新偏好 | 在相应类别中追加 | 在"最爱吃的"列表中增加新项 |
| 更新记忆-场景映射 | 追加新的映射行 | 为新记忆添加对应的场景映射 |

#### soul.md 的补丁操作

| 操作类型 | 方式 | 示例 |
|---------|------|------|
| 新增行为规则 | 在Layer 0末尾追加 | 新标签检测到后，追加翻译后的行为规则 |
| 更新语言指纹 | 修改Layer 2的表格 | 发现新的口头禅，追加到列表 |
| 更新情感逻辑 | 修改Layer 3的表格 | 发现新的情感表达方式，补充到触发表 |
| 更新关系动态 | 修改Layer 4的描述 | 新增"对其他子女"的关系描述 |
| 新增矛盾 | 在内在矛盾部分追加 | 发现新的性格矛盾，追加记录 |
| 新增示例对话 | 补充Layer 2的场景对话 | 用新素材中的真实对话替换或补充示例 |

**绝对禁止的操作：**
- 删除现有的行为规则（除非用户明确要求）
- 修改用户确认过的描述
- 降低已确认条目的置信度
- 覆盖Layer 5中的用户修正

### 第六步：重新生成 SKILL.md 的灵魂摘要

如果合并导致灵魂档案有重大变化（新增标签、重要矛盾解决、信心度变化超过5%），重新生成灵魂档案摘要卡片。

**信心度重新计算规则：**

```
基础信心度 = 
  聊天记录贡献（0-40分）+
  口述记忆贡献（0-20分）+
  口头故事贡献（0-15分）+
  书信/日记贡献（0-15分）+
  第三方信息贡献（0-10分）

加成：
  多源交叉验证：+5分
  用户修正后确认：+3分/次（最多+10分）
  
总分映射到百分比：线性映射0-100
```

## 边界情况处理

### 大量新素材（超过500条消息）

- 分批处理，每批100条
- 每批处理完后向用户报告进度
- 优先处理情感浓度高的素材

### 来自不同家庭成员的素材

- 标记素材来源（"来自用户姐姐的视角"）
- 同一事件的不同视角都保留
- 对逝者性格的描述如有差异，不合并，而是记录"在不同人面前的不同面"

### 用户说"之前说的不对，TA其实..."

- 这不是新增素材，而是修正
- 转入 correction_handler.md 流程
- 更新Layer 5（修正层），同时可能需要修改更高层的规则
